Where does a new file go?

You are adding…Put it inRule
A new LLM step or graph nodesrc/agents/<stage>/<step>.py + src/prompts/<step>/ + models.yaml entrySame name in all three places.
Structured-output model for a stepsrc/agents/schemas/<step>_schema.pySchemas hold no logic.
A deterministic check / fix on planssrc/agents/planning/Pure code, unit-tested, no LLM call.
A deterministic fix on XMLsrc/compiler/ (Python) or src/node/ (needs POM measurement)Rules as data go to src/knowledge/.
Rule, limit, palette, icon listsrc/knowledge/core|components|theme/Data, not code; one source per fact.
A one-off experiment runnerscripts/experiments/<name>/Never imported from src/; close it out when the experiment ends.
A reusable eval / maintenance toolscripts/eval/ or scripts/tools/Run as python -m scripts.<group>.<name>.
A testtests/unit/test_<module>.py; data in tests/fixtures/<topic>/Unit tests never need a key.
A design note, spec, research docdocs/<topic>-YYYY-MM-DD.mdNever at the project root.
Results of a run worth keepingdocs/eval/<experiment>/ (text + small renders)Raw runs stay in output/ / llm_test/.
Upstream / client reference materialdocs/reference/Client-confidential files never go in git.

Migration phases

Phase 1 · Root clean-up done in this branch

No Python import or command changes. References updated in AGENTS.md, .cursor/rules/pom-compiler-constraints.mdc, tests/LLM_TEST_PLAN.md, docs/CODE_REVIEW.md and tests/unit/test_upstream_reference.py (reads llm.md). Unit suite unchanged against the baseline.

  • ARCHITECTURE.md, CODE_FLOW.md, EDITING_ARCHITECTURE.md, flow.md → docs/architecture/
  • CODE_REVIEW.md, GENOFFICE_FEATURE_ADOPTION.md → docs/
  • llm.md, GJ_H1 performance deck.pptx → docs/reference/ (pptx renamed gj-h1-performance-deck.pptx)
  • plan.txt, NEW_CHAT_CONTEXT.txt (git root) → docs/archive/; otherpc_test.txt → docs/eval/
  • Deleted src/node/compile-pom.txt, src/node/package.txt (stale copies, no references)

Phase 2 · Group scripts/ after feat/tile-nodes merges

Move into eval/, tools/, experiments/<name>/. Every moved script's ROOT = parent.parent becomes parents[2] (or [3]), ~30 from scripts.x import lines and the test imports change, and every python -m scripts.x command in AGENTS.md and the docs changes. Wait until the tile experiment closes so the test-PC commands don't break mid-run. Closed experiments are the moment to delete rather than move.

Phase 3 · Split src/agents/ one mechanical PR

Create planning/, generation/, review/, schemas/ and src/services/; rewrite imports with a script, run the full unit suite, no behaviour change in the same PR. Do it between feature branches, when no other branch has open edits in src/agents/, to avoid merge conflicts.
