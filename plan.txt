# POM XML Generation MVP — Final Plan

> All open questions resolved. Ready for implementation.

---

## 1. Objective & Hypothesis

**Hypothesis**: A smaller, structured, component-specific POM context produces more accurate POM XML than supplying the complete 12,000-token `llm.txt` documentation.

**Current state**: A Python script concatenates `user.txt` + `llm.txt`, sends to GPT-4o/4.1, and gets back POM XML that consistently fails validation due to HTML contamination, invented attributes, and zero-value errors.

**Target state**: A pipeline that selects only the POM constructs relevant to the requested slide, constrains the LLM with an explicit allowlist, and produces compilable POM XML at a measurably higher rate.

## 3. POM Error Classification (Confirmed from Testing)

Three distinct error types, each requiring different handling:

### Type 1: ParseXmlError — Unknown Tag
```
ParseXmlError: XML validation failed (1 error):
  - Unknown tag: <br>
errors: [ 'Unknown tag: <br>' ]
```
- **Thrown by**: `parseXml()` (before layout/render)
- **`errors` property**: `string[]` — machine-parseable
- **Pattern**: `"Unknown tag: <X>"` — extract tag name with regex
- **Cause**: LLM invented HTML/non-POM elements
- **Retry strategy**: Tell LLM which tags are invalid, list allowed tags

### Type 2: ParseXmlError — Unknown Attribute
```
ParseXmlError: XML validation failed (1 error):
  - <Text>: Unknown attribute "className"
errors: [ '<Text>: Unknown attribute "className"' ]
```
- **Thrown by**: `parseXml()` (before layout/render)
- **`errors` property**: `string[]` — machine-parseable
- **Pattern**: `"<Node>: Unknown attribute \"X\""` — extract node and attribute
- **Cause**: LLM used HTML/CSS/React attributes
- **Retry strategy**: Tell LLM which attributes are invalid on which node, list allowed attributes

### Type 3: Render Error — Invalid Values
```
Error: addTextBox: width must be a finite positive EMU value
```
- **Thrown by**: `@pptx-glimpse/document` during PPTX rendering (after parse succeeds)
- **No `errors` array** — just `error.message` string
- **Cause**: Zero or negative dimension values that pass XML parsing but fail at render
- **Retry strategy**: Tell LLM the specific constraint violated, show the node that caused it

### Diagnostic Classifier Design
```javascript
function classifyError(error) {
  if (error.name === 'ParseXmlError' && error.errors) {
    return {
      stage: 'parse',
      type: error.errors.some(e => e.startsWith('Unknown tag')) ? 'UNKNOWN_TAG' : 'UNKNOWN_ATTRIBUTE',
      details: error.errors,
      retryable: true
    };
  }
  if (error.message?.includes('must be a finite positive')) {
    return {
      stage: 'render',
      type: 'INVALID_VALUE',
      details: [error.message],
      retryable: true
    };
  }
  return {
    stage: 'unknown',
    type: 'UNCLASSIFIED',
    details: [error.message || String(error)],
    retryable: false
  };
}
```

## 4. Known Failure Patterns & Mitigations

### 4.1 HTML Contamination (Critical — most common failure)

The LLM's HTML/CSS training priors overwhelm POM-specific instructions when given 12K tokens of reference documentation.

| What LLM generates | What POM expects | Fix in prompt |
|-------------------|-----------------|---------------|
| `<br/>`, `<div>`, `<p>`, `<hr/>` | `<Text>`, `<VStack>`, `<HStack>` | Explicit blocklist + allowlist |
| `style="..."`, `class="..."` | Individual attributes: `fontSize="24"` | "Do NOT use style= or class=" |
| `width: 100%`, `font-size: 24px` | `w="100%"`, `fontSize="24"` | Show exact POM syntax in examples |
| `#FF0000` | `FF0000` | "Colors: 6-digit hex WITHOUT # prefix" |

### 4.2 Invented Attributes

| What LLM generates | What POM expects | Fix in prompt |
|-------------------|-----------------|---------------|
| `className`, `onClick` | (doesn't exist) | "Use ONLY these attributes" allowlist |
| `flex`, `justify`, `align` | `grow`, `justifyContent`, `alignItems` | Side-by-side "NOT this → use this" table |
| `width`, `height` | `w`, `h` | Prominent note: "w/h NOT width/height" |

### 4.3 Zero/Invalid Values

| What LLM generates | What POM expects | Fix in prompt |
|-------------------|-----------------|---------------|
| `w="0"`, `h="0"` | Positive numbers | "All dimensions must be > 0" |
| `gap="0"` | Positive number or omit | "Omit gap instead of setting to 0" |
| `opacity="2"` | 0–1 range | Include value ranges in attribute definitions |

### 4.4 Post-Generation XML Sanitizer

Before sending to `buildPptx()`, run a pre-validator that:
1. Strips markdown fences (` ```xml ... ``` `)
2. Checks for known HTML tags (`<br>`, `<div>`, `<p>`, `<hr>`, `<span>`)
3. Checks for `style=` and `class=` attributes
4. Checks for `#` prefix on color values
5. Checks for zero-value dimensions
6. Logs all violations in `evaluation.json`
7. Optionally auto-fixes simple issues (strip `#` from colors, remove `<br/>` tags)

### 5.3 compile-pom.js (Node.js Compiler)
```javascript
// compile-pom.js — thin wrapper, no business logic
import { readFile, writeFile, mkdir } from 'fs/promises';
import { buildPptx } from '@hirokisakabe/pom';
import path from 'path';

const inputPath = process.argv[2];
const outputDir = process.argv[3] || './output';

async function compile() {
  await mkdir(outputDir, { recursive: true });
  const xml = await readFile(inputPath, 'utf8');
  const result = {
    status: null,
    pptxPath: null,
    diagnostics: [],
    pomVersion: '10.3.0'
  };

  try {
    const { pptx } = await buildPptx(xml, { w: 1280, h: 720 });
    const pptxPath = path.join(outputDir, 'presentation.pptx');
    await pptx.writeFile({ fileName: pptxPath });
    result.status = 'success';
    result.pptxPath = pptxPath;
  } catch (error) {
    result.status = 'failure';
    if (error.name === 'ParseXmlError' && error.errors) {
      result.diagnostics = error.errors.map(e => {
        if (e.startsWith('Unknown tag:'))
          return { type: 'UNKNOWN_TAG', message: e };
        if (e.includes('Unknown attribute'))
          return { type: 'UNKNOWN_ATTRIBUTE', message: e };
        return { type: 'PARSE_ERROR', message: e };
      });
    } else {
      result.diagnostics = [{
        type: 'RENDER_ERROR',
        message: error.message
      }];
    }
  }

  const resultPath = path.join(outputDir, 'compile-result.json');
  await writeFile(resultPath, JSON.stringify(result, null, 2));
  process.exit(result.status === 'success' ? 0 : 1);
}

compile();
```

## 6. Prompt Strategy Design

### 6.1 Baseline Prompt (for comparison)
```
SYSTEM:
You are a POM XML generator. Generate valid POM XML for presentations.

{full contents of llm.txt — ~12,000 tokens}

USER:
{user request from test case}
```

### 6.2 Selective Context Prompt (the improvement)
```
SYSTEM:
You generate POM XML for @hirokisakabe/pom v10.3.0.
Return ONLY valid POM XML. No explanation, no markdown fences, no code blocks.

═══ CRITICAL RULES ═══

POM XML is NOT HTML. Do NOT use any HTML elements or attributes.

FORBIDDEN — never use these:
  Tags:  <br>, <br/>, <div>, <p>, <span>, <hr>, <hr/>, <section>, <header>, <footer>
  Attrs: style, class, className, onClick, id (except for Arrow connectors)
  Props: width (use w), height (use h), font-size (use fontSize),
         text-align (use textAlign), flex-direction (use VStack or HStack)
  Colors: Do NOT prefix with # — use FF0000 not #FF0000
  Values: All dimensions (w, h, gap, padding) must be > 0. Never use 0.

═══ ALLOWED NODES ═══
{dynamically selected from pom-knowledge/core/nodes.yaml based on SlideIR}

═══ ALLOWED ATTRIBUTES ═══
{dynamically selected from component YAML files}

═══ THEME ═══
{default theme tokens from pom-knowledge/theme/default.yaml}

═══ LAYOUT PATTERN ═══
{selected layout from pom-knowledge/layouts/}

═══ REFERENCE EXAMPLE ═══
{1-2 compile-verified examples from pom-knowledge/examples/}

═══ SLIDE OBJECTIVE ═══
{from SlideIR.objective}

═══ REQUIRED COMPONENTS ═══
{from SlideIR.components}

USER:
{user request + any supplied business content}
```

### 6.3 Key Differences
| Aspect | Baseline | Selective |
|--------|----------|-----------|
| Context size | ~12,000 tokens | ~2,000–4,000 tokens |
| Constraint style | Implicit (reference doc) | Explicit (allowlist + blocklist) |
| HTML prevention | None | Explicit FORBIDDEN section at top |
| Examples | None | 1-2 verified, compilable examples |
| Layout guidance | None | Specific layout pattern for this slide |
| Value constraints | Buried in doc | Prominent rules section |

## 10. Success Criteria

### Minimum Viable Result
- [ ] Pipeline runs end-to-end (request → PPTX)
- [ ] At least 3/9 test cases produce valid PPTX with selective context
- [ ] Selective context produces fewer `ParseXmlError` than baseline
- [ ] Token usage is measurably lower with selective context
- [ ] All intermediate artifacts are saved and inspectable

### Strong Result
- [ ] Selective context achieves >70% PPTX success rate
- [ ] Zero HTML contamination errors with selective context
- [ ] Component completion rate >80%
- [ ] Token usage reduced by >60% vs baseline
- [ ] At least one retry converts a failure to success

### The MVP is complete when
It produces measurable evidence showing whether selective POM context improves generation accuracy compared to the full `llm.txt` prompt. A negative result (selective context doesn't help) is still a valid completion — the experiment answers the question either way.
