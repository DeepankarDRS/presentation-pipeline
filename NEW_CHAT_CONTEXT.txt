## What We Are Building

An MVP that proves one hypothesis:

> **Selective, component-specific POM context fed to an LLM produces more accurate POM XML than sending the full 12,000-token `llm.txt` reference document.**

The output is a CLI tool that takes a natural-language slide request and produces a compiled `.pptx` file using `@hirokisakabe/pom`.

## Critical Implementation Constraints

### 1. Clean-Slate Implementation
- No existing codebase to reference or extend
- Write every file from scratch
- No hardcoded paths anywhere — everything relative or from env vars

### 2. Portable / Importable
- Code will be written in this session and transferred to a different computer for testing
- Must work on Windows (target machine) — use `path.join()` not forward-slash strings
- All config in `.env` file — never hardcode API keys or model names

### 3. No Live API Testing
- OpenAI API key is on a different computer — do NOT call the API during development
- Write complete, correct code that can be tested immediately on import
- Include `.env.example` with placeholder values
- Include a `--dry-run` flag on `generate.py` that skips the LLM call and uses a hardcoded sample XML instead — this lets the compiler and evaluator be tested without an API key

### 4. No Existing PoC
- Previous PoC was a simple 2-file script (user.txt + llm.txt → LLM → XML) on a different machine
- We are NOT migrating or adapting it — full new implementation

## Confirmed POM Error Shapes

These were confirmed by running tests against `@hirokisakabe/pom` v10.3.0.
The compiler wrapper must handle exactly these three shapes:

### Type 1 — Unknown Tag (ParseXmlError)
```
ParseXmlError: XML validation failed (1 error):
  - Unknown tag: <br>
error.name === "ParseXmlError"
error.errors === [ 'Unknown tag: <br>' ]
```

### Type 2 — Unknown Attribute (ParseXmlError)
```
ParseXmlError: XML validation failed (1 error):
  - <Text>: Unknown attribute "className"
error.name === "ParseXmlError"
error.errors === [ '<Text>: Unknown attribute "className"' ]
```

### Type 3 — Invalid Value (Render Error)
```
Error: addTextBox: width must be a finite positive EMU value
error.name === "Error" (regular Error, no .errors array)
error.message contains "must be a finite positive"
```

## The Core Failure Pattern (Why We're Building This)

The previous PoC consistently failed because the LLM **leaks HTML/CSS mental models into POM XML**:

| LLM generates (wrong) | POM expects (correct) |
|----------------------|----------------------|
| `<br/>`, `<div>`, `<p>` | `<Text>`, `<VStack>`, `<HStack>` |
| `style="..."`, `class="..."` | Individual POM attributes |
| `className`, `onClick` | (don't exist in POM) |
| `width`, `height` | `w`, `h` |
| `#FF0000` | `FF0000` (no `#` prefix) |
| `w="0"`, `h="0"` | Must be > 0 |

The selective prompt strategy fixes this with an explicit **FORBIDDEN** blocklist before any reference material.

## Key Design Decisions to Respect

- `compile-pom.js` writes `compile-result.json` to the output dir and exits with code 0 (success) or 1 (failure)
- `compiler_client.py` calls it via subprocess, reads the JSON, never parses Node errors from stderr
- `generate.py --dry-run` skips LLM, uses `pom-knowledge/examples/text-slide.xml` as the "generated" XML — lets you test the full pipeline without an API key
- `generate.py --strategy baseline|selective` switches between full llm.txt and selective context
- Both strategies are implemented and compared — that's the whole point of the MVP
- `evaluation.json` is machine-readable for later aggregation across test runs
- All YAML example snippets in the knowledge base must be **compile-verified** (actually tested against buildPptx)
- Use `pathlib.Path` throughout Python — never os.path string concatenation

## POM XML Rules (Enforce in Prompt and Pre-Validator)

### Required structure
```xml
<Slide>
  <Theme surface="0F172A" accent="3B82F6" textMain="F8FAFC" textMuted="94A3B8" />
  <VStack w="1280" h="720" padding="48" gap="24" backgroundColor="0F172A">
    <!-- content nodes here -->
  </VStack>
</Slide>
```

### Hard rules
- `<Slide>` is mandatory wrapper (breaking change in v10+)
- `<Theme>` goes inside `<Slide>`, before layout nodes
- Colors: 6-digit hex, NO `#` prefix
- All dimensions: must be positive numbers (never 0)
- `w="max"` fills available width, `w="50%"` is valid
- Dot-notation for nested: `border.width="1"`, `border.color="334155"`, `border.radius="8"`
- No HTML elements ever: `<br>`, `<div>`, `<p>`, `<span>`, `<hr>`
- No HTML/CSS attributes ever: `style`, `class`, `className`, `width`, `height`, `font-size`

### Phase A nodes only (for initial generation)
```
Slide, Theme, VStack, HStack, Text, B, I, Span, Mark, Shape
```
